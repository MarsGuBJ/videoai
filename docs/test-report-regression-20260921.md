## 失败用例与缺陷（两轮均复现，远程结论为准）

1. **【待需求确认】上传复核任务弹窗「事件编码」下拉数据源是复核类型而非事件信息**（TC-RWGL-016、TC-SJPZ-023 失败，本地+远程均复现）
   - 页面：万物核-任务管理 → 上传复核任务（「事件判断」弹窗）
   - 实际：`ModalHost.vue` 该下拉选项来自 `GET /api/review-types`，仅在事件配置建了事件信息但未建复核类型的事件不出现；显示格式「名称（编码）」本身正确。复核类型/布控任务两处下拉均确认来自事件信息，仅上传复核任务弹窗例外。
   - 用例预期：选项来自事件配置的事件信息。若产品口径为「上传复核必须挂复核类型（提示词）」，则属用例描述滞后，需需求侧确认后同步修订用例。
2. **【疑似 bug】接口异常 toast 兜底文案不可达**（TC-SJLB-011、TC-SJTJ-007 失败，本地+远程均复现）
   - 页面：事件列表 /events、事件统计 /stats
   - 复现：接口返回 500 或网络中断 → toast 显示「Internal Server Error」/「Failed to fetch」，而非用例预期的「事件列表加载失败」/「事件统计加载失败」。
   - 原因：`EventsPage.loadEvents` / `StatsPage.loadStats` 的 catch 分支为 `e instanceof Error ? e.message : "兜底文案"`，fetch 与 HTTP 错误均为 Error 实例，兜底文案永远不会出现。万物核任务管理页接口失败时同样透出英文「Failed to fetch」。
3. **【疑似 bug】事件趋势图按 UTC 日期填充，与本地时区错位**（TC-SJTJ-002 失败，本地 SQLite 与远程 PostgreSQL 均复现）
   - 页面：事件统计 /stats
   - 复现：默认最近 7 天（本地 09-15~09-21），趋势图渲染 8 个柱（09-14~09-21），标签整体偏前一天；本地清晨事件计入前一日的柱。
   - 原因：前端把本地日期转 UTC ISO 后，后端按 UTC 日期补齐趋势并分组。
4. **【口径不一致】统计「未复核」与列表「待复核」筛选口径不同**
   - 统计接口把 review_status 非「有效/无效」的记录全部计为未复核；列表筛选「待复核」仅匹配 NULL/空串。远程现场数据下两口径一致（未复核 5 = 待复核 5），仅当库中存在字面量「待复核」的 review_status 记录时对不上（本地轮出现 20≠18）。建议后端统一口径以防真实复核链路写入字面量后偏差。

## 其他发现的问题（不阻塞，未计入失败）

1. **布控任务详情页「算法编号」恒显示「—」**（本地+远程均复现）：`DeployTasksPage.vue mapTaskToRow` 未把 `algorithmCode` 带进行对象，详情页取不到值（后端数据正常）。
2. **布控任务详情页大量静态占位**（本地+远程均复现）：生效时间固定「全天」、相似度固定 85%、告警概览「高优先级 3 条/复核通过 6 条/最新告警 2026-07-16 14:32:08」写死；「启停任务」「刷新状态」按钮仅弹模拟 toast 无实际效果；「编辑任务」按钮打开的是空白新建弹窗而非编辑回填。
3. **新建布控任务切换「算法编号」会静默清空已选人脸目标**（源码注释标明为有意设计）：先选人脸后选算法时布控目标被清空，保存时才被校验拦截，无前置提示。
4. **已停用的事件信息仍出现在复核类型/布控任务下拉中**：`ReviewTypeListPage.vue` 与 `ModalHost.vue` 的事件下拉均未按 `enabled` 过滤，停用事件仍可被新业务引用。
5. **无算法/版本删除接口**：远程回测创建的算法只能停用无法删除；事件亦无删除接口（见现场遗留）。
6. **toast 仅展示约 1700ms**：快速连点或自动化断言时易错过提示，供后续用例设计参考。

## 环境问题（非产品缺陷）

1. **现场检索服务故障（远程，影响万物搜链路）**：`/api/text-search/query`、`/api/person-search/detect-persons` 均返回 500（traceId 65a771b68f2d4516b2d406c2894ff311），导致 TC-BKRW-014 快速布防无法从检索结果发起，建议现场排查。
2. **nginx upstream 缓存 IP 导致 502（远程，已修复）**：backend 容器重建后 frontend nginx 仍解析旧 IP，5173/api 全部 502；重启 frontend 容器恢复。后续重启 backend 容器后建议联动重启 frontend。
3. **现场遗留数据（远程）**：① 2 个「回测BK-」算法处于已停用状态（无删除接口）；② 2 条「回测SJ-」测试事件滞留 deployment_events（无删除接口/DB 权限），如需清理请现场运维执行：`DELETE FROM deployment_events WHERE face_profile_name LIKE '回测SJ-%' OR camera_name LIKE '回测SJ-%';` 其余回测数据（布控任务、复核任务/类型/定时任务、事件信息、去重规则、推送任务及注入事件）均已删除核实。
4. **大模型研判链路未验证（两轮同）**：本机与现场的「测试大模型」均为占位地址，复核任务终态为「失败」，「已完成 + 有效/无效判定」路径需可用大模型环境补测。
5. **backend-lite SQLite 模式（仅本地轮）**：`Base.metadata.create_all` 因 `algorithm_versions.missing_files`、`deployment_tasks.camera_ids` 使用 PostgreSQL ARRAY 类型渲染失败，建表被跳过，算法/布控任务/事件信息等仅存内存，服务重启即丢失（deployment_events 由运行时迁移单独建表不受影响）。远程为 PostgreSQL 无此问题。
