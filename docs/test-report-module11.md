## 发现的缺陷

1. **【P1】新增/编辑设备缺少 IP、端口格式校验**（TC-SBGL-004）：非法 IP `999.999.999.999`、非数字端口 `abc` 均可保存成功，直接写入设备库。~~建议前端在向导第 2 步增加 IP/端口格式校验，后端同步增加入参校验。~~ **已修复（2026-09-14）**：前端向导/编辑页保存前校验 IPv4 格式与端口范围（1-65535），后端 `CameraCreateRequest`/`CameraUpdateRequest` 增加 `@Pattern` 校验，并新增 `CameraRequestValidationTest` 单测。
2. **【P2】通道号无边界校验**（TC-SBGL-005）：通道号 0、超大数值（99999）均可保存。~~建议限制通道号取值范围。~~ **已修复（2026-09-14）**：前后端统一限制通道号为 1-256 的整数，越界/非数字均拦截并提示。
3. **【建议】必填校验覆盖不足**（TC-SBGL-003）：仅设备名称必填，设备编号/IP/端口等关键接入参数未做必填约束（仅在无法拼装拉流地址时兜底拦截）。**已修复（2026-09-14）**：未手填拉流地址且协议可自动拼装（RTSP拉流/RTMP推流/HTTP拉流）时，IP、端口为必填；通道号必填且校验边界。

修复涉及文件：

- 前端：`frontend/src/utils/regions.ts`（新增 `isValidIPv4`/`isValidPort`/`isValidChannelNo`/`canComputeSourceUrl`）、`frontend/src/pages/MediaDeviceWizardPage.vue`、`frontend/src/pages/MediaDeviceEditPage.vue`
- 后端：`backend/monitoring-common/.../dto/CameraCreateRequest.java`、`CameraUpdateRequest.java`、新增测试 `backend/monitoring-core/src/test/java/com/videoai/monitoring/core/validation/CameraRequestValidationTest.java`

验证情况：`npm run build`（含 vue-tsc）通过；后端 monitoring-common/monitoring-core 全量单测通过（含新增校验单测 5 例）。修复已于 2026-09-14 部署到 10.10.3.100（本地构建产物推送 + 远程重建镜像，涉及容器 frontend / frontend-media / backend-media），部署后全量 UI 回归通过：TC-SBGL-003/004/005 复测通过，其余用例无回归。
