## 发现的缺陷

1. **【P2】国标接入页缺少"平台名称"列**（TC-JRPZ-003 相关）。**已修复（2026-09-14）**：后端 GB28181/GA1400 两张配置表新增 `name` 字段并在响应中透出；前端两表新增"平台名称"首列，新增/编辑弹窗增加平台名称输入（非必填，缺省显示"-"）。复测验证列展示与名称回填正常。
2. **【P2】接入配置页无平台在线/离线状态展示**（TC-JRPZ-004 相关）。**已修复（2026-09-14）**：后端新增 `AccessConfigStatusProbeService`，`@Scheduled(60s)` 对启用中的 GB28181（sipIp:sipPort）/GA1400（platformIp:port）条目做 TCP connect 探测（2.5s 超时，线程池并行，停用条目标记 UNKNOWN），结果落库 `online_status`/`last_check_at` 并在列表响应透出；前端新增"状态"列显示 在线/离线/未知。**已知限制（如实记录）**：GB28181 SIP 信令通常走 UDP 5060，TCP 可达性探测对纯 UDP 端点会显示"离线"，该场景下状态列不可作为真实在线依据。
3. **【P1】编辑接入配置保存失败：PUT 被 CORS 拦截（复测新发现）**：在页面对已有 GB28181/GA1400 条目点"编辑"、修改平台名称后点"确定"，浏览器 PUT `/api/access-config/gb28181/entries/{id}`（及 ga1400 对应接口）返回 **403 Invalid CORS request**，前端提示"GB28181 配置保存失败：Invalid CORS request"，弹窗不关闭、数据未保存。同路径的 POST（新增）与 DELETE（删除）从浏览器均正常（200），无 Origin 头的直连 PUT 也正常（200），定位为后端 CORS 配置未放行 PUT 方法。复现截图：`shots/40-diag-gb-edit-save.png`、`41-ga-edit-cors.png`。**已修复（2026-09-14）**：`WebConfig.java` CORS allowedMethods 补充 PUT（OPTIONS 预检已验证 200）。补验通过：UI 编辑 GB28181/GA1400 条目（改名称+端口）保存成功，toast 正常、弹窗关闭、列表与 API 数据同步生效，见回归记录。补验截图：`shots/53-cors-gb-edit-saved.png`、`54-cors-ga-edit-saved.png`。
