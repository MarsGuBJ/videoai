# 实时预览摄像头批量导入设计

## 目标

将附件中的 359 条摄像头记录导入 VideoAI 实时预览。导入必须识别同一设备下的多个实际视频通道，避免把双光谱或球机/云台设备的多路画面错误映射到同一个通道。

## 输入与范围

- 数据源为用户提供的 Excel 附件，共 359 条有效摄像头记录。
- 记录覆盖 336 个唯一设备地址，其中 23 组设备地址对应两条摄像头记录。
- 摄像头名称、区域和设备类型沿用 Excel 原值。
- 设备登录凭据由部署环境提供，不写入仓库代码、测试、文档或日志。
- 本次只处理实时预览摄像头导入及按需启动视频流，不修改录像下载和其他 MCP 接口。

## 通道发现与映射

1. 按设备地址去重，对 336 台设备分别查询设备能力、RTSP 服务端口和实际视频通道。
2. 优先使用海康 ISAPI 查询流通道；ISAPI 不可用时使用部署环境已有的 HCNetSDK 能力查询。
3. 单记录设备映射到查询结果中的主码流通道。
4. 同地址多记录设备按设备返回的通道名称、通道编号和 Excel 中的画面类型匹配：
   - 普通画面与热成像画面映射到不同传感器通道。
   - 球机与云台枪机映射到各自实际通道。
   - 名称完全重复的记录使用 Excel 序号保持独立，并映射到尚未分配的实际通道。
5. 只有唯一匹配时才生成导入项。无法唯一匹配的记录进入异常清单，不使用固定 `101/201` 猜测。

## 导入模型

- 使用“Excel 序号 + 摄像头名称 + 设备地址”作为导入标识。
- 导入前读取远程现有摄像头列表，按导入标识和实际 RTSP 地址去重。
- 已存在且映射一致的记录跳过；已存在但映射变化的记录更新；不存在的记录新增。
- `name`、`area` 使用 Excel 值，`nvrId` 保存设备地址，`nvrChannel` 和 `nvrTrackId` 保存实际查询结果。
- 凭据只进入远程运行配置所需的数据，不进入本地仓库。

## 视频启动策略

- 批量导入的摄像头初始状态为 `STOPPED`，避免部署或后端重启时同时拉取 359 路视频。
- 实时预览页面发现当前可见摄像头尚未运行时，调用现有启动接口拉起对应 ZLMediaKit 代理，并更新页面状态。
- 切换单画面或分屏时只启动新出现的可见摄像头，不批量启动隐藏摄像头。
- 不自动停止已经启动的摄像头，避免影响其他正在观看同一路视频的客户端。

## 错误处理与可恢复性

- 导入前备份远程摄像头持久化目录。
- 设备不可达、认证失败、通道查询失败和通道映射歧义分别记录，不中断其他设备。
- 导入过程可重复运行；重试只处理缺失、变化或上次失败的记录。
- API 新增或更新失败时记录请求对象的非敏感标识和错误，不输出凭据或完整 RTSP URL。

## 验证

- 校验 Excel 有效记录数为 359、唯一设备数为 336、重复地址组数为 23。
- 校验导入后不存在重复导入标识，且每条成功记录的实际通道唯一、可追溯。
- 覆盖单设备、双光谱设备、球机/云台设备、名称重复记录和不可达设备的映射测试。
- 验证实时预览初次加载只启动当前可见摄像头。
- 部署后核对摄像头总数、异常清单和容器状态，并抽样验证不同区域以及同设备双画面的 FLV 流头与有效视频数据。

## 部署

1. 备份目标服务器摄像头配置。
2. 部署实时预览按需启动改动并重建前端。
3. 在目标服务器网络内执行通道发现和幂等导入。
4. 验证后端、前端和 ZLMediaKit 状态以及抽样视频流。
